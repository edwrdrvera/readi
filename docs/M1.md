# M1: reader feasibility and persistence

Status as of 2026-09-28. This file records M1 decisions, verified behavior, and open issues so another session can continue. The requirements are in *Book Reader App — Spec v1.1*, section 11.

## Launch

Prerequisites: Xcode Command Line Tools, Node 26, pnpm 12, and Rust stable (`brew install rustup && rustup default stable`).

```bash
pnpm install
pnpm tauri dev                       # development window
pnpm tauri build --bundles app,dmg   # packaged app and DMG
open src-tauri/target/release/bundle/macos/Readi.app
```

Import books with ⌘O or by dropping `.epub` and `.pdf` files on the window. Click a book to read it. Use the arrow keys or Space to turn pages.

## Decisions

- **Resource transport.** `book://localhost/<book id>` resolves the id through SQLite and never accepts a path. PDF.js reads through a `PDFDataRangeTransport` subclass that issues `Range` requests. It does not use PDF.js's own fetch loader, which starts with an unbounded full-file GET. EPUBs, which are archives, are fetched whole up to 512 MiB.
- **PDF chunk size is 16 KiB.** PDF.js prefetches every top-level `/Pages` kid. With 256 KiB chunks, opening the flat-tree fixture read 158 MB.
- **PDF extraction reopens the document every 50 pages.** PDF.js retains fetched chunks for the document's lifetime, and text extraction fetches whole image XObjects.
- **PDF text uses `streamTextContent` with an explicit reader.** `getTextContent` uses `for await` over a `ReadableStream`, which WKWebView does not support.
- **CSP** is set in `tauri.conf.json`. `style-src` keeps `'unsafe-inline'` through `dangerousDisableAssetCspModification`, because EPUB `<style>` elements need it and a Tauri nonce would disable it. `script-src` stays nonce-only, so book scripts cannot run. Blob iframes inherit this policy.
- **Import** copies the file to `.staging`, hashes the staged bytes, then publishes it by atomic rename to `library/<sha256>.<ext>`. Launch deletes staging leftovers and unreferenced managed files.
- **Migrations** use `PRAGMA user_version`. The database is backed up with `VACUUM INTO` before any migration after the first.
- **Background throttling is disabled** so extraction continues while the window is hidden. WebKit honors this on macOS 14 and later only.
- **UI.** M1 uses plain CSS. shadcn/ui and Tailwind are deferred to M2, per the spec's instruction to resolve the M1 risks before broad UI work.

## Open issues

1. **macOS 13 unverified.** The following are known compatibility points: `Object.groupBy`, `Map.groupBy`, and `Promise.withResolvers` are polyfilled in `src/polyfills.ts`; PDF.js uses its legacy build; the Vite target is `safari16`; background throttling cannot be disabled before macOS 14. Run the packaged check on macOS 13 before confirming the minimum.
2. **Occluded window pauses PDF rendering.** WebKit stops `requestAnimationFrame` for covered windows, and PDF.js rendering waits on it. The self-test calls `setFocus` first. Users see pages render when the window becomes visible.
3. **Peak memory during PDF extraction is not measured.** Retention is bounded by the 50-page reopen, but no footprint was recorded during extraction.
4. **Warm open is single-sample.** The spec requires p95 over 20 opens.
5. **Console error on EPUB close.** foliate's paginator calls `expand()` on a document that is already gone and throws `Cannot destructure property 'documentElement'`. Reading is unaffected.
6. **Self-test hooks ship in the release binary.** They are gated by `READI_SELFTEST`, and `selftest_report` writes only to that path. Remove them or compile them out before release.
7. **Unsigned build.** Signing credentials are an open decision.
8. **Not implemented in M1:** menus (⌘O is a key handler), TOC sidebar, themes, scroll mode, and covers. Drag-and-drop import is wired but untested.
