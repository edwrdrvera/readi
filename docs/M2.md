# M2: reading experience

Status as of 2026-09-28. This file records M2 decisions, verified behavior, and open issues so another session can continue. The requirements are in *Book Reader App — Spec v1.1*, sections 5, 6 (Contents), 9, and 11. M1 decisions stand; see [M1.md](M1.md).

## Launch

Prerequisites and build steps are unchanged from M1.

```bash
pnpm install
pnpm tauri build --bundles app
open src-tauri/target/release/bundle/macos/Readi.app
```

Import with File > Import… (⌘O), the Import… button in the Library, or by dropping `.epub` and `.pdf` files on the window. Open Settings with the gear button in the Library or the reader toolbar. In a book, **Aa** changes settings for that book only.

## What M2 adds

| Area | Behavior |
| --- | --- |
| Reading modes | EPUB: vertical scroll, or horizontal pages in 1 or 2 columns. PDF: vertical stacked pages, or horizontal single page or two-page spread. The spread shows page 1 alone, then pairs (2,3), (4,5). |
| Themes | Light, Dark, Sepia, and Follow system (the default). PDFs keep their original pages. Sepia overlay and dark inversion are optional PDF effects, off by default. |
| Typography | Publisher default, Serif, Sans; font size stepper (12–36 px); line height 1.3, 1.5, 1.7, 1.9. |
| PDF zoom | Fit width, fit page, or a numeric scale set by ⌘+ and ⌘−. |
| Preferences | Settings holds the global defaults. **Aa** writes per-book overrides to `book_preferences`. Reset to defaults deletes the book's overrides. |
| Contents | The sidebar (⌘\\) highlights the active entry. Clicking an entry jumps there and records Back history for the book. Back (⌘[) returns without recording. EPUBs without navigation get a flat spine list. PDFs without an outline list physical pages, with printed labels shown separately. |
| Progress | Vertical scrolling saves after 500 ms idle and at least every 2 s. Page turns and jumps save immediately. Progress is also saved on blur, on returning to the Library, on switching books, and on close. |
| Restore | The same passage stays in view after mode, typography, zoom, and window-size changes. An unresolvable EPUB CFI falls back to its section and shows "Restored an approximate position". An out-of-range PDF page is clamped and shows "Restored to the nearest available page". |
| Keyboard | Every §9 shortcut that applies to M2. Reading shortcuts never act inside editable controls. Escape closes the foremost popover, sheet, or unpinned sidebar and returns focus to its opener. |
| Chrome | The toolbar hides after 2 s without activity and stays visible while it holds focus or a popover or sheet is open. |
| RTL | EPUB page order follows the book's direction. Left and Right map through it. |
| Menus | App, File (Import…), Edit (standard), View (Contents, mode, themes, text size), Go (Back, Return to Library), Window. |

### M2 packaged checks

All run in `Readi.app` through `src/selftest.ts`. The EPUB and PDF restore checks take an anchor before the change and assert, after `settled()`, that the same anchor is still visible. For EPUB the anchor is the start of the visible text. For PDF it is a PDF-space point: mid-page in vertical mode, and the containing page in horizontal mode.

- **Theme persistence.** A default of Sepia and a Dark override on text.pdf survive SIGKILL and relaunch. The Library shows sepia, text.pdf shows dark, and the EPUB text color matches Sepia. Reset on text.pdf returns it to sepia and deletes its overrides.
- **EPUB restore.** The passage stays visible across these changes: horizontal to vertical, vertical to horizontal, one to two columns, serif, font size +2 steps, line height 1.9, and a window resize from 1000×760 to 750×608.
- **PDF restore.** The point stays visible across these changes: fit width to 2×, 2× to fit page, fit page to fit width, vertical to horizontal, horizontal to vertical, and a window resize.
- **RTL order.** In rtl.epub, in both single and two-column mode, goLeft and ArrowLeft advance and goRight goes back.
- **Approximate restore.** A bogus CFI restores to its saved section (3, not 0) and shows the notice.
- **Scroll saves.** During continuous vertical scrolling, the first save lands about 620 ms in, while the scroll is still running.
- **Back.** A contents jump moves away, and Back returns to the previous CFI with that passage visible.

## Decisions

- **One preference model.** `src/lib/prefs.ts` defines every preference key. Settings writes defaults, **Aa** writes per-book overrides, and the reader receives the two merged. Theme follows the same rule, so ⌘1–3 while reading set that book's theme and in the Library set the default. Rust validates every value at the boundary (`src-tauri/src/prefs.rs`), and `PrefKey` is an enum, so no column name comes from the frontend. Defaults are stored as versioned JSON in `app_settings`. Migration 2 adds `book_preferences.pdf_effect`.
- **Follow system is resolved in script.** `html[data-theme]` always holds a concrete theme, so the chrome and the book cannot disagree.
- **EPUB vertical mode is continuous at section edges.** foliate's scrolled flow shows one section at a time. Scrolling past a section edge (more than 150 px of overscroll, Down, or Space) moves into the adjacent section. A renderer with several iframes was rejected as too large for M2.
- **Scroll saves sample the position.** foliate reports a scrolled position only after scrolling stops. The EPUB reader samples every 500 ms during a scroll so ProgressSaver can meet the 2 s maximum.
- **The PDF reader is a class inside a React wrapper.** It positions canvases absolutely over placeholders sized from each page, renders only visible pages plus one on each side, and releases the rest. The stored locator is the source of truth for every relayout (prefs, resize, late page sizes).
- **One command registry** (`src/lib/commands.ts`). The window keydown handler, the forwarded keydown from each EPUB section document, and the native menu all run commands from it. Chords that are menu accelerators are skipped by the keydown handler, so a command runs once whether or not WebKit also delivers the key.
- **shadcn/ui components are hand-written** in shadcn's style on the `radix-ui` package: Button, Sheet, Popover, ToggleGroup, Separator, and ScrollArea. `components.json` lets the CLI take over later.
- **foliate patch.** `patches/foliate-js@1.0.1.patch` makes `expand()` return when the section document is gone. `fonts.ready` could resolve after close and throw. This fixes M1 open issue 5.
- **Hidden windows in the self test.** When the app opens on another Space, WebKit reports it hidden and pauses `requestAnimationFrame`. The self test drives frames by timer while hidden. This does not help when the screen is **locked**, because WebKit then also stops applying layout (open issue 4).

## Open issues

1. **Native menu accelerators are not observed.** The agent environment had no Accessibility or Automation access. Check by hand that View > Sepia and ⌘3 each change the theme once, and that ⌘O opens the import dialog. If an accelerator does not fire, that shortcut does nothing, because the keydown handler defers to the menu.
2. **Chrome auto-hide, wheel-driven section changes, and the UI's look are unverified.** Behavior was checked through DOM probes. Nobody has looked at the UI.
3. **Always show controls** (spec §9) is not implemented.
4. **The packaged check needs the display on and the screen unlocked.** Otherwise WebKit does not apply layout. The PDF restore checks fail (7 failures) and scroll speeds drop.
5. **Clamped PDF scroll can desynchronize.** If WebKit clamps `scrollTop` while layout is stale, `PdfView.place()` records the clamped value. The view could show a different page from the stored locator until the next resize. Seen only with the screen locked.
6. **Two-column RTL order.** The check proves that page turns go in the right direction. It does not prove that the right-hand column comes first.
7. **RTL section fraction.** The first page of an RTL section reports `section_fraction` of about 0.2 instead of about 0. This comes from foliate's page arithmetic and was not investigated.
8. **Zoomed horizontal PDF pages.** The position is saved at the page's top-left, so panning within a zoomed page is not saved.
9. **Tailwind v4 needs Safari 16.4.** macOS 13.3 and later ship it. Earlier macOS 13 releases do not. This adds to the macOS 13 check (M1 open issue 1).
10. **M1 carry-overs still open.** macOS 13 runtime; peak memory during PDF extraction; warm open p95 over 20 opens; drag-and-drop import untested; self-test hooks in the release binary; unsigned build.
