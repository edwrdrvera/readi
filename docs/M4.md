# M4: search and annotations

Status as of 2026-09-29. This file records M4 decisions, verified behavior, and open issues so another session can continue. The requirements are in *Book Reader App — Spec v1.1*, sections 6, 7, 8, 10 (Search and Progress rows), and 11. Earlier decisions stand; see [M1.md](M1.md), [M2.md](M2.md), and [M3.md](M3.md).

M4 is on `feat/m4-search`, off `main` (d2fa347). It also carries the M3 gap fixes from `fix/m3-gaps`.

## Launch

```bash
export PATH=/opt/homebrew/opt/rustup/bin:$PATH
pnpm install
pnpm tauri build --bundles app
open src-tauri/target/release/bundle/macos/Readi.app
```

In a book, press ⌘F to search it, ⌘D to add a bookmark, and select text to highlight it. Press ⌘⇧F anywhere to search the library. The reader sidebar (⌘\) has Contents, Annotations, and Search tabs.

## What M4 adds

| Area | Behavior |
| --- | --- |
| Text mappings | Each segment (an EPUB section or a PDF page) stores its indexed text and a versioned mapping (`src/lib/textmap.ts`). Units are the section's text nodes or the page's PDF.js text items, counted with empty ones so indexes are stable. Whitespace is replaced one-for-one, so an offset inside a unit is the same in the raw and indexed text. Extraction and the readers enumerate units with the same functions. Extractor version is 2 for both formats. |
| Indexing | `replace_text` replaces a book's segments in one transaction. A segment whose mapping fails validation keeps its text and stores no mapping, and its hits open as approximate. On launch, jobs left `indexing` are reclaimed and books indexed below version 2 are requeued. Progress and annotations are untouched. States are Queued, Indexing, Ready, No searchable text, and Failed. Book Info offers Retry for a failed job and Rebuild search index. |
| Query | `search.rs` parses plain text into words and quoted phrases. It quotes every token for FTS5, so operators stay literal. Matching ignores case and diacritics, as the FTS5 tokenizer does. A query uses at most 16 terms. Word segmentation for languages written without spaces is not guaranteed. |
| In-book search | ⌘F opens the Search tab. Hits are ordered by position and grouped by section or page, with snippets. Rust converts each hit to unit points. The reader rebuilds the DOM range and checks its text against the hit before calling it exact. Otherwise it opens the section or page and shows an "approximate" notice. The panel distinguishes still indexing, no searchable text, failed (with Retry), and no matches. |
| Library search | ⌘⇧F opens a dialog. Title or author matches come first, then books by text relevance with up to 3 hits each. A status line counts books still indexing, without text, or failed. |
| Highlights and notes | Selecting text shows a popover with four colors and Add note. EPUB highlights store a range CFI, the quote, and context. PDF highlights store quads in PDF page space, drawn through the current viewport, so they follow zoom. Notes save 600 ms after typing stops and flush on blur, navigation, return to Library, and close. A failed save keeps the draft and shows Retry. |
| Bookmarks | ⌘D, the toolbar, or the palette. A bookmark stores the current locator. It works on image-only PDF pages. |
| Anchor resolution | An EPUB highlight is resolved when its CFI range still reads as its quote. Otherwise the quote is searched for in the same section, and context breaks ties. A unique match is resolved. No match, or a tie, is unresolved. PDF highlights are unresolved only when their page is out of range. The state is persisted (`annotations.anchor_state`). Unresolved annotations stay listed, marked, filterable, and openable as approximate. |
| Annotations tab | Lists highlights and bookmarks in reading order (`sort_key`) with a filter over quotes and notes. |
| PDF text layer | Rendered pages get a PDF.js text layer and an SVG highlight overlay. Both are released with the page. |

### M4 packaged phases

The phases share a fresh data dir and end in SIGKILL. Node reads the database between phases.

- **m4-index.** Searching large.pdf while it indexes reports still indexing, in the book and in the library. The app is killed mid-index, with the job `indexing` and no segments stored.
- **m4-search.** After relaunch, large.pdf finishes indexing. Every segment has a mapping, and each book's segments share one extractor version. image.pdf is No searchable text. The phase covers in-book search in EPUB and PDF: ordering, grouping, words, phrases, no matches, exact jumps, and a corrupted range opening as approximate. It also covers library search, a forced failure with Retry, a rebuild with identical results and untouched progress and annotations, and 20 timed queries.
- **m4-annotate.** Highlights from a programmatic selection in EPUB and PDF. The PDF highlight still overlaps its text after zoom. The phase adds a note, edits a color, deletes a highlight, and adds ⌘D bookmarks in an EPUB and in image.pdf. It creates one unresolved EPUB highlight and one that recovers by quote, and checks the filter.
- **m4-restart.** Annotations, notes, colors, bookmarks, and anchor states survive the kill, and highlights redraw. Search still works, and a far hit in large.pdf opens. The memory sampler is on.

## M3 gaps closed here

- **Exclusions survive folder removal.** Migration 4 keys `watched_exclusions` by folder path. `exclusion_survives_removing_and_readding_the_folder` failed before the fix, and a packaged check covers removal and re-add.
- **Palette for the focused card.** In the Library, Mark as Finished, Mark as Unread, and collection actions apply to the focused card and name it.
- **A flaky M3 check.** `locationAt` in `selftestM3.ts` read the book summary before its locations. A reconcile that committed between the reads failed a random live step. It now reads the summary afterward.
- **Memory breakdown.** See open issue 3.

## Decisions

- **Rust converts hits to unit points.** The mapping stays in the database, and the reader receives `[unit, offset]` pairs and verifies the text. A mismatch means approximate, never a wrong range.
- **Offsets are UTF-16.** They match JavaScript strings. Mapped segments skip the whitespace-collapsing `clean_text` and are only bounded and stripped of control characters one-for-one.
- **Anchor state is stored.** The reader resolves anchors when a book opens and persists the result, so the list can mark unresolved annotations without rendering every section.
- **⌘F, ⌘⇧F, and ⌘D are keydown-owned.** The Go menu lists Find in Book, Search Library, and Add Bookmark without accelerators, following the M2 rule that a chord belongs to either the menu or the keydown handler.
- **Matching folds diacritics.** "cafe" finds "café", because FTS5 unicode61 already folds them and Rust must agree to show hits.

## Open issues

1. **Manual checks still owed.** Real ⌘F, ⌘⇧F, and ⌘D keystrokes, the three new Go menu items, real mouse selection, clicking a drawn highlight, the popover's placement, and the look of the new UI. Also everything in M3 open issue 2.
2. **The search corpus is synthetic.** The 500 ms target is met by a wide margin on a generated corpus. The spec's corpus of real books was not built.
3. **Peak footprint during the first phase is 559 to 668 MB** over 5 runs. The breakdown at the peak: WebContent about 500 MB, of which the JS VM Gigacage (typed-array buffers) is about 290 MB and WebKit malloc about 160 MB. The app is 70 to 80 MB, GPU about 65 MB, and Networking 8 MB. The peak falls at the end of extraction, not while reading. PDF.js allocates a buffer the size of the file per document in its worker, and extraction opens a fresh document every 50 pages. A branch that reuses one PDF.js worker for the whole run (`exp/pdf-shared-worker`) peaked at 516 MB in one run. That is within the range without it, so it is not merged. Proving a win needs several paired runs.
4. **Bookmark anchor states stay `unknown`.** Only highlights pass through `setAnnotations`, so bookmark states are never persisted. Bookmarks resolve whenever their section or page exists.
5. **Library search returns every matching book.** It has no limit or truncation flag. A much larger library would need one.
6. **Invalid XHTML sections.** foliate renders them as HTML, but `createDocument()` yields a parser error document, so their text and mapping may not match what is shown. No fixture covers this.
7. **PDF rotation.** Quad conversion is unit-tested at 0, 90, 180, and 270 degrees. No fixture has `/Rotate`.
8. **Deleting an annotation has no confirmation or undo.**
9. **Carry-overs.** Hidden-window PDF checks (M3 open issue 1): a regression run with the window hidden failed 6 PDF restore checks, all reporting `visibilityState` hidden. `claim_cover_job` (M3 issue 5), unreadable files (M3 issue 6), macOS 13, self-test hooks in the release binary, unsigned build.
