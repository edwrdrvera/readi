# M3: library and file lifecycle

Status as of 2026-09-29. This file records M3 decisions, verified behavior, and open issues so another session can continue. The requirements are in *Book Reader App — Spec v1.1*, sections 4, 6 (Library organization), 8, 9, and 11. M1 and M2 decisions stand; see [M1.md](M1.md) and [M2.md](M2.md).

M3 was built on `feat/m2-reading`. PR #19 and the M2 release (PR #20) merged into `main` before M3 did.

## Launch

Prerequisites are unchanged from M1.

```bash
pnpm install
pnpm tauri build --bundles app
open src-tauri/target/release/bundle/macos/Readi.app
```

Import with File > Import… (⌘O), the Import… button, drag and drop, or Finder's Open With. Add watched folders in Settings. Press ⌘K for the command palette.

## What M3 adds

| Area | Behavior |
| --- | --- |
| Import | Every import is a persisted job (`import_jobs`): queued, running, then done, failed, or cancelled. `import_books` only inserts rows, so the UI responds at once. One worker thread copies to `library/.staging/<job id>` while hashing, then publishes by atomic rename. Jobs that run over 1 s show progress, and every job can be cancelled. |
| Identity | A book is one SHA-256. A known hash with a managed copy focuses the existing card. A known hash without one (watched only) gains a managed copy. |
| Open With | `Info.plist` declares EPUB and PDF as Viewer document types. `RunEvent::Opened` queues the files as import jobs. |
| Watched folders | `watch.rs` runs one reconcile thread. It scans on launch, then reconciles after `notify` (FSEvents) hints, coalesced until 500 ms of quiet. Files younger than 2 s wait. A hash is verified stable by comparing stat before and after reading, with up to 3 retries. |
| Reconcile | Symlinks and hidden files are skipped. Nested folders are walked once, with each file attributed to the deepest folder. A file renamed or moved inside the folders is relinked by hash. A file moved out or deleted becomes `moved`. Changed bytes at a path re-point that location to a new book, and the old book keeps its progress. The planner is pure (`plan` returns typed actions), and `apply` commits them in one transaction. Hashing never holds the database lock. |
| Availability | Each location is `available`, `folder_unavailable`, `permission_denied`, or `moved`. A book is Missing only when no location is available. This is derived in SQL and never stored. Book Info shows each location and offers Locate. |
| Reading watched files | `book://` compares a watched file's size and mtime with the recorded values before serving it. On a mismatch it answers 409 and requests a rescan, and the reader returns to the Library with a notice. |
| Removal | Remove from Library deletes the book's records in one transaction, records a `watched_exclusions` row for each watched folder, and commits before deleting the managed copy and cover. Watched originals are never touched. Delete Managed Copy is a separate action and refuses when it is the only location. Settings > Excluded Books restores an exclusion. |
| Organization | Filters for format, author, reading state, and availability, and sorts by recently opened, title, author, or date added, all with ties broken by id. The view persists in `app_settings` (`ui`). Mark as Finished or Unread. Covers are extracted in the extraction queue before text, with a placeholder when missing. |
| Collections | Manual collections allow many-to-many membership. A watched folder can show as a derived, read-only collection. Deleting a collection keeps its books. Removing a folder deletes its locations and derived collection and keeps books and progress. |
| Command palette | ⌘K opens a shadcn `Command` dialog over the command registry. It also offers contextual commands: reading state and collection membership for the open book, showing a collection, New Collection, the four themes, Back, Return to Library, and Import. |
| Always show controls | A Settings switch keeps the reader toolbar visible (spec §9). |

### M3 packaged checks

The M3 phases use a second data dir. Node makes every outside change. While the app runs, the self-test logs `fs:<step>` and waits for the library to change, and node answers each step. After a phase, node reads the database with `node:sqlite` and lists the library directory.

- **m3-live-import.** The store acknowledges an import in 1 ms and the DOM in 3 ms. All 5 fixture copies import. A 2 GB sparse PDF shows a progress bar after 1 s, is cancelled, and leaves no staging file and no book row. Re-importing `typical.epub` focuses the existing card. A synthetic `tauri://drag-drop` imports a file and toggles the drop overlay. `open -a Readi.app <file>` reaches the running instance and imports the file.
- **m3-kill / m3-recover.** The app is SIGKILLed with 417 MB in staging, and node deletes that source. After relaunch the job has failed with an actionable reason and the queued job behind it completes. Staging is empty, every library file is a managed location, every managed location has its file, and there is no book row for the killed file.
- **m3-watch-live.** One hash in two folders gives one card with two locations. Add, move into a subfolder, move out, delete, changed bytes (the old book keeps its progress), and `chmod 000` each produce the expected location state, all through file events without a manual rescan. Importing a watched-only book adds a managed copy. A removed book stays out after a rescan. ⌘K opens the palette, and Mark as Finished runs exactly once.
- **m3-watch-offline.** The same changes made while the app is closed, plus `chmod 000` on a folder root, are reconciled by the launch scan. The exclusion holds after that scan, and restoring it brings the book back. The collection, the folder collection, the view (sort, format, collection), and the Finished state all survive the restart.

## Decisions

- **Jobs are the source of truth for imports.** A job becomes done in the same transaction as its book and location rows. The file is published before that commit, so a kill in between leaves only an unreferenced managed file, which the launch reconcile deletes. Jobs left `running` are requeued on launch.
- **Changed bytes re-point the location row.** `upsert_location` on an existing `(kind, path)` moves it to the new book. The old book keeps progress and annotations, and anchors are never transferred.
- **Locate** verifies the hash. Inside a watched folder it relinks the location. Outside, it makes a managed copy, because the schema has only managed and watched locations.
- **Remove from Library deletes the managed copy.** Delete Managed Copy is the separate option for books that also have a watched location. A managed-only book has no library record left to keep its copy, and launch reconcile would delete the file anyway.
- **⌘K is not a menu accelerator.** The Go menu lists Command Palette without a shortcut. The keydown handler owns ⌘K, which lets a synthetic keydown drive it, in keeping with M2's rule that a chord belongs to either the menu or the keydown handler.
- **Covers** are regenerable files in `covers/<book id>`, at most 1 MiB, PNG or JPEG. `cover_state` is `pending`, `ready`, `none`, or `failed`. They are served at `book://localhost/<id>/cover`, and `img-src` allows `book:`.

## Open issues

1. **Hidden window.** In M2 this appeared only with the screen locked or the display off. It also happens when Readi opens hidden behind another Space or full-screen app, with the display on and the screen unlocked. The same 7 PDF restore checks fail, on the M2 app too. Keep the desktop visible during `packaged-check.mjs`.
2. **Manual checks still owed.** Nothing here was checked with real keystrokes or clicks, because agents had no Accessibility or Automation access. Check by hand:
   - View > Sepia and ⌘3 each change the theme once.
   - ⌘O opens import.
   - ⌘K opens the palette.
   - A real Finder drag imports.
   - Chrome auto-hide works, and Always show controls keeps the toolbar.
   - The look of the Library, Book Info, dialogs, and palette. Nobody has looked at the UI.
3. **Peak memory is 619 MB** during the `first` phase, which includes extracting the 263 MB PDF and reading it. The spec has no extraction limit, but this is 4× the idle target. The next step is a per-process breakdown.
4. **Palette in the Library.** Reading-state actions appear only for an open book, not for the focused card.
5. **`claim_cover_job` does not mark a book claimed.** This is safe with one extraction queue. A second consumer would process the same book twice.
6. **A file that appears unreadable is skipped** rather than recorded as `permission_denied`. It is added once it becomes readable and an event or rescan arrives.
7. **Deleting a watched folder deletes its exclusions** (foreign key cascade). Adding the folder again can restore books the user removed.
8. **Carry-overs.** macOS 13 runtime (and Tailwind v4 needs Safari 16.4); `PdfView.place()` clamped scroll (M2 open issue 5); self-test hooks in the release binary; unsigned build.
